# 用户调研

## 工作流程
1. 明确调研目标：确定要验证的假设或要探索的未知领域，界定目标用户范围
2. 使用 `web_search` 搜集行业报告、竞品用户反馈、应用商店评论，汇总已有认知
3. 设计调研方案：选择合适的方法（问卷 / 深度访谈 / 可用性测试 / 日志分析），拟定访谈提纲或问卷题目
4. 分析调研数据：归类整理用户反馈，提炼关键发现，标注样本量和置信度
5. 构建用户画像：抽象 2-4 个典型用户角色，含基本信息、行为特征、目标、痛点
6. 使用 `fs_write` 输出调研报告到 `user-research-{项目}-{日期}.md`

## 访谈提纲建议
- 漏斗式提问：从宽到窄，先问行为再问动机
- 避免引导性问题：不问"你是不是觉得…"，改问"当时你是怎么做的"
- 追问技巧：对关键事件要求用户还原具体步骤和时间线
- 每次访谈控制在 30-45 分钟，聚焦 3-5 个核心问题

## 输出格式
- 调研概述：目标、方法、样本描述、执行时间
- 关键发现（按优先级排列，每条附带用户原话）
- 用户画像（含虚构姓名、照片描述、一句话特征）
- 行动建议（产品改进方向，标注优先级）
- 附录：完整问卷 / 访谈提纲 / 原始数据摘要
