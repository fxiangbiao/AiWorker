# 演示与汇报

## 工作流程
1. 明确汇报场景与受众：管理层汇报 → 强调战略价值与 ROI；投资人路演 → 强调市场机会与增长潜力；团队评审 → 强调执行细节与技术方案
2. 使用 `web_search` 搜索行业数据、竞品对标、市场趋势，为论点提供外部佐证
3. 构建叙事结构：推荐 SCQA 框架（情境 → 冲突 → 问题 → 答案）或黄金圈法则（Why → How → What）
4. 设计页面结构：每页一个核心观点，标题即结论，正文用数据/图表支撑
5. 打磨结尾：总结 3 个关键 takeaway，明确下一步行动（Call to Action）
6. 使用 `fs_write` 输出演示大纲到 `presentation-{主题}-{日期}.md`

## 页面设计原则
- 10-20-30 法则：不超过 10 页，不超过 20 分钟，字号不小于 30pt
- 一页一观点：每页只传达一个核心信息，支撑数据不超过 3 条
- 图表优于表格：趋势用折线图，对比用柱状图，占比用饼图/环形图
- 文字精炼：每页文字不超过 40 字，用关键词替代完整句子

## 输出格式
- 演示信息卡：主题、场景、受众、时长、日期
- 叙事主线（一句话概括你想让听众记住什么）
- 分页大纲（每页含：核心观点、支撑数据/案例、过渡语）
- 关键数据引用（标注来源）
- 预期问答准备（3-5 个可能被问到的问题及应答要点）
- 附录建议（备用数据页、详细方案页）
