# PRD 撰写

## 工作流程
1. 确认产品定位与目标用户，使用 `web_search` 调研竞品功能与行业基准
2. 梳理功能列表：按 P0/P1/P2 优先级分级，标注每项功能的用户价值与实现复杂度
3. 明确非功能性需求：性能指标（响应时间、并发量）、安全合规要求、兼容性约束
4. 定义验收标准：每项功能对应可量化的完成条件，使用 GWT（Given-When-Then）格式
5. 评估风险与依赖：技术难点、外部 API 依赖、团队资源瓶颈，给出缓解方案
6. 使用 `fs_write` 将文档输出为 `prd-{项目名}-{版本号}.md`

## PRD 文档结构
- 文档信息：版本号、作者、日期、变更记录
- 产品概述：一句话定位 + 核心价值主张
- 用户画像：目标用户特征、痛点、使用场景
- 功能范围：当前版本包含/不包含的功能
- 功能详述：每条功能含背景、流程图（文字描述）、交互说明、异常处理
- 数据指标：定义成功的量化指标（DAU、转化率、NPS 等）
- 附录：术语表、参考资料链接

## 输出要点
- 语言简洁，避免技术黑话，确保设计师和运营人员都能理解
- 每个功能点标注优先级标签：🔴 P0 / 🟡 P1 / 🟢 P2
- 验收标准必须可测试，不能使用"体验好""流畅"等模糊表述
