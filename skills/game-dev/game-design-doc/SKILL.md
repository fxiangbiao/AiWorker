# 游戏设计文档 (GDD)

## 工作流程
1. 明确游戏类型（动作、RPG、策略、模拟等）与目标平台，确定设计范围。
2. 使用 `web_search` 检索同类游戏的设计参考与最佳实践，提炼可借鉴的核心机制。
3. 按标准 GDD 结构组织文档：概述 → 核心玩法 → 系统设计 → 美术风格 → 技术需求。
4. 用 `fs_write` 将完整设计文档输出到指定路径，每个章节独立成段。

## 核心机制设计
- 明确游戏的**核心循环**（core loop）：玩家在 30 秒内不断重复的最小行为闭环。
- 描述主要**交互方式**：点击、拖拽、按键映射等，确保操作直觉化。
- 列出**胜负条件**与**玩家动机**：分数、进度、排行、叙事驱动等。

## 系统模块拆解
- 关卡系统：关卡数量、难度曲线、解锁条件。
- 成长系统：等级、技能树、装备提升路径。
- 经济系统：货币类型、获取渠道、消耗出口。
- 社交系统（如适用）：排行榜、好友、公会。

## 输出格式
```markdown
# {游戏名称} 设计文档

## 概述
- 游戏类型 / 目标平台 / 核心体验

## 核心玩法
- Core Loop 图示与文字说明
- 操作方式与交互逻辑

## 系统设计
- 各子系统详细说明（关卡 / 成长 / 经济 / 社交）

## 美术风格
- 视觉方向、色调参考、UI 风格参考

## 技术需求
- 引擎 / 工具链 / 性能目标
```
