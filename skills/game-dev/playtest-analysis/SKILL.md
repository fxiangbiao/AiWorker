# 玩家测试分析

## 工作流程
1. 用 `fs_read` 读取玩家测试反馈数据（问卷、日志、录屏记录、内部测试笔记等）。
2. 将定性反馈分类为：可用性问题（操作困惑、UI 难懂）、难度问题（太简单/太难）、体验问题（无聊、挫败、困惑）。
3. 将定量数据（通关率、死亡次数、关卡时长）与设计预期值对比，定位偏差显著的节点。
4. 用 `fs_write` 输出测试分析报告，包含问题清单、严重程度排序和改进建议。

## 分析维度
- **上手体验**（0-10 分钟）：新玩家能否独立理解基础操作？哪些教学提示被忽略或跳过？
- **核心循环吸引力**：玩家在用哪种方式玩游戏（激进/保守/探索）？这种玩法是否与设计意图一致？
- **摩擦点定位**：玩家重复死亡/重试的关卡节点是哪里？该节点的设计意图是什么？为什么玩家卡住？
- **退出行为分析**：玩家在哪个阶段停止游戏？退出前的最后一个操作是什么？

## 难度曲线验证
- 统计每个关卡的首次通关率、平均通关时长、平均死亡次数。
- 画出现实难度曲线与设计曲线的对比图（文字描述），标记偏差 > 30% 的关卡。
- Boss 关的玩家心率（通过死亡密度间接衡量）应为普通关卡的 1.5-2 倍，过低则 Boss 无压迫感，过高则劝退。

## 反馈归类与优先级
- **P0 阻塞性问题**：导致玩家无法继续的 Bug、UI 无法点击、关键路径缺失引导。
- **P1 体验问题**：频繁出现的操作困惑、过度惩罚（过长的跑尸路）、难度尖刺。
- **P2 优化建议**：动画节奏微调、文本易读性、音效适耳度等锦上添花项。

```markdown
- [ ] 问题描述 → 建议方案

### P1 体验问题
- [ ] ...

### P2 优化建议
- [ ] ...

## 改进路线图
- 短期修复（下一版本） / 中期优化（2-3 个版本内） / 长期观察
```
